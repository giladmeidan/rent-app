## Deviations from the spec

- Four dev dependencies not named in Scope: `@types/react`, `@types/react-dom`, `@types/node`, `@testing-library/dom` (peer of `@testing-library/react` 16). Recorded under the spec's "Risks / open questions" for the orchestrator.
- TypeScript 5.9.3, not the latest 7.x: `typescript-eslint` 8.72 needs `<6.1`, `openapi-typescript` 7.13 needs `^5`.
- `i18next` 27.0.1 and `typescript-eslint` 8.72.1 instead of the newest patch releases: pnpm 12's default `minimumReleaseAge` (1 day) rejects 27.1.1 / 8.72.2, published within the last day; picking older versions avoids a `minimumReleaseAgeExclude` list.
- Makefile gained `test-api`, `test-web`, `lint-api`, `lint-web` so CI jobs run one half each (the `api` job has no Node). `make test` / `make lint` still run everything.
- The CI `e2e` job runs `make dev` rather than a bare `compose up`: migrate and seed run from the host through uv, and without the seed `/areas` is empty and AC8 cannot pass. So the job also sets up uv.
- No `web/public/manifest.webmanifest` file: the manifest is generated from `vite.config.ts`. The checker reads only `.tsx`, so both whitelisted files are outside its input by construction (documented in the script header).
- `ErrorState` reads `common.error` / `common.retry` itself and takes only `onRetry`; `EmptyState` takes the message.

## Out of scope, noticed (not fixed)

- TanStack Query's default `retry: 3` with backoff means the real app shows the error state after about 7 s of failures; tests use `retry: false`. A later slice may want a shorter policy.
- `lint-web` generates `schema.d.ts` only when it is missing; after an API change a developer must run `make client` (README says so; CI always regenerates).
- GitHub Actions logs Node deprecation warnings from `pnpm/action-setup@v4`, `actions/setup-node@v4` and `setup-uv@v6`; pnpm warns about a deprecated transitive `glob@11.1.0`.
- No CI step runs `vite build`; the PWA output was verified by hand only. Slice 9 owns installability.
- Making `web` and `e2e` required checks is a branch-protection setting for Gilad.
