# Review 0001a — round 1 (code, qa, security) — 2026-11-09

**blockers 0 · majors 1 (all three reviewers) · minors 8 (deduped) · nits 14** → REQUEST CHANGES

## Majors
1. `api/app/services/auth.py:92-105` `_count_request` — all three counters are INCRed before the limits are checked, so a 429'd request still burns the daily per-email budget and the IP budget. Repro (qa + security): 10 requests for one email from one IP → `[204×3, 429×7]`, `rl:otp:email:day` = 10; after the 15-min key expires the next request is 429 with `Retry-After: 86400`. Anyone can lock any email out of login for 24 h in a second; a real user tapping "resend" ~10 times locks themselves out. Code adds: an IP-limited request also increments the victim's email counters. **Fix:** one Lua script that GETs all three counters; if any is at its limit return that TTL and increment nothing; otherwise `SET k 0 EX w NX` + `INCR` each. AC17 (503 still counts) unchanged. **Tests:** `test_ac16_burst_of_429s_does_not_consume_daily_budget` (after 3×204 + 7×429 the day counter is 3; delete the 15-min keys; next request 204) and `test_ac7_ip_limited_requests_do_not_count_against_email`.

## Minors
1. `api/app/schemas/auth.py:22` — `display_name` accepts NUL (→ Postgres DataError → **500**, attempt not refunded, OTP key survives), bidi controls, zero-width and other Cc/Cf/Zl/Zp characters (invisible or spoofable names). Fix: field validator rejecting categories Cc/Cf/Zl/Zp (allow ZWJ/ZWNJ if needed) → 422; add cases to the AC11 parametrize (`"\u0000\u0000"`, `"​​"`, `"a\nb"`). (code, qa, security)
2. `api/app/services/auth.py:142-171` — one correct code can open two sessions when two verifies race (key deleted after commit). Fix: claim the code atomically in the reservation script (compare-and-delete on matching HMAC, or `HSETNX claimed`), restore on commit failure. (qa)
3. `api/app/services/auth.py:147-148,155` — delete-after-5th-wrong and the profile_required refund are separate calls, not keyed on the reserved `code_hmac`: a concurrent `request_otp` in between gets its fresh code deleted, or its attempts pushed to -1 (6 guesses). Fix: compare-and-delete / compare-and-refund in Lua on `HGET code_hmac == ARGV`. (code, security)
4. `api/app/config.py:44-48` + `api/app/services/email.py:52-58` — malformed `SMTP_URL` passes `Settings()` and fails per request with a 500; `urlsplit(...).port` ValueError can echo part of the password into the traceback (`smtp://u:pa/ss@host`). Fix: parse/validate scheme, host and port in the Settings model validator (`hide_input_in_errors` already on), raise a fixed message `from None`. (code, qa, security)
5. `api/app/main.py:41` — a Redis outage turns `/auth/otp/*` into text/plain 500; Postgres already gets a JSON 503. Fix: handler for `redis.exceptions.ConnectionError`/`TimeoutError` → 503 `ErrorOut`, or FOLLOWUP. (qa)
6. `api/app/config.py:29-34` — production can start with the public dev `SECRET_KEY`, `cookie_secure=False` and the file backend and work silently. Fix (cheap): when `web_origin` is https, reject the dev key and require `cookie_secure=True` and an explicit `EMAIL_BACKEND`; else FOLLOWUP for Slice 12. (security)
7. **Deployment constraint, spec/FOLLOWUPS not code** — `SameSite=Lax` needs web and API on one registrable domain. PRODUCT.md's Cloudflare Pages + Fly/Railway would be `*.pages.dev` + `*.fly.dev` (both on the public suffix list) → the cookie is never sent and 0001b breaks in prod. Slice 12 must serve both under one domain (app.X / api.X). Record in spec Risks and FOLLOWUPS. (security)
8. **FOLLOWUP for Slice 12** — no per-IP limit on `/auth/otp/verify`, no global send cap, IPv6 keyed per /128; ~960 code requests/day per IP across emails. Blocked on real client IPs behind the proxy. (security)

Residual accepted risk (orchestrator): even after major 1 is fixed, the 10/day cap lets an attacker lock a chosen account out with 10 requests over ~45 min. Accepted for MVP; revisit in Slice 10 (trust) with an email-confirmed unlock or a soft cap. Recorded in the spec's Risks.

## Nits (14, folded, no action)
