# Deploying homie to production

The one runbook for production (spec 0013a): the API, worker, Redis and admin on Fly.io in Frankfurt, Postgres on
Fly Managed Postgres (MPG), the web on Cloudflare Pages. Secrets appear here by **name only**; a value is a
`<placeholder>` or is generated by the command shown. Nothing below has run against a real account yet.

**Tool versions these commands were checked against (2026-11-18):**

| Tool | Version | How |
| --- | --- | --- |
| `flyctl` | **not run**; checked against docs on 2026-11-18 (latest release then: v0.5.12) | Not installed on the build computer. Flags come from docs.fly.io/flyctl and, where noted, flyctl's public source |
| `wrangler` | 4.156.1 (`WRANGLER_VERSION` in the `Makefile`) | `--help` of `login`, `pages deploy`, `pages project create` |
| `openssl` | 4.1.0 | `openssl rand -help` |

**Confirmed from flyctl's source, not only its docs:** `fly deploy`'s `--dockerfile` resolves against the current
directory (so the `make` targets run from the repo root), the build context's `.dockerignore` is read from the
working directory `.`, and `fly scale count` accepts `app=1 worker=1`. Fly's docs show `fly ssh console -C "printenv"`
listing secrets, so `-C` commands get the app's environment.

**Still unconfirmed until the first real run. If one differs, stop and bring it to the orchestrator:**
- every `fly` flag has been read, never executed: run `fly version` and compare `--help` where something fails;
- what `fly mpg users create` prints (its docs do not say); section 7 therefore takes the password from
  `fly mpg users rotate-password`, whose docs say it prints the new one;
- how a Reader behaves on a real MPG cluster (section 7 probes it first);
- the Grafana metric query in section 11, written from Fly's metrics docs without an account.

Each section is done once unless it says otherwise. Day-to-day deploys are section 11.

## 1. Accounts (Gilad, once)

1. Create a Fly organisation with billing. `brew install flyctl`, then `fly auth login`.
2. Cloudflare (the account exists for R2): `cd web && pnpm dlx wrangler@4.156.1 login`.
3. Buy the domain, add it to Cloudflare (free plan) and point the registrar's nameservers there.
4. On the deploy computer: Node `>=22.12 <23`, pnpm, uv, and a **dedicated clean checkout of `main`**. Every
   `make deploy-*` refuses a checkout that has local commits or untracked files, so do not use a working checkout.
5. **Keep only homie's apps in this Fly organisation.** All its apps share one private network. Gilad accepted that
   for launch on 2026-11-18, relying on the 16+ character admin password, the Redis password and the admin login lock.
6. Create the apps:

   ```sh
   fly apps create homie-api
   fly apps create homie-redis
   fly apps create homie-admin
   ```

   Fly app names are global. If one is taken, pick another and change, through a PR: `app` in its toml, the
   `*.internal` host in `REDIS_URL`, the `-a` values here and the CNAME target in section 6.

## 2. Postgres

```sh
fly mpg create --name homie --enable-postgis-support --pg-major-version 16 --plan Basic --region fra --volume-size <GB>
```

Choose `--volume-size` deliberately: storage is $0.28 per GB a month (10 GB is the default). Then, **before the
first deploy**, enable PostGIS. A schema admin gets `permission denied to create extension`; with this done,
migration `0001`'s `CREATE EXTENSION IF NOT EXISTS postgis` is a no-op:

```sh
fly mpg databases extensions enable postgis --cluster <cluster id> --database <db>
fly mpg connect <cluster id> -d <db> -c "select extname, extnamespace::regnamespace from pg_extension where extname = 'postgis'" -c "show max_connections"
```

- PostGIS must be in schema `public` (`alembic/env.py` pins `search_path=public`).
- `max_connections` must be at least 50 (API 15 + worker 15 + admin 15 + release 1).
- In the dashboard's Connect tab copy the **direct** connection string (host `direct.<cluster>.flympg.net`, not the
  `pgbouncer` one) and change its scheme to `postgresql+psycopg://`. That is `DATABASE_URL`.

## 3. Redis

```sh
fly volumes create redis_data --size 1 --region fra -a homie-redis
openssl rand -hex 32   # keep it in the password manager: it is also part of REDIS_URL (section 6)
fly secrets import --stage -a homie-redis   # paste the line below, then Ctrl-D
```

```text
REDIS_PASSWORD=<redis password>
```

```sh
make deploy-redis

```

## 4. Photos

1. Create the production R2 bucket. Give it the custom domain `media.<domain>` and leave `r2.dev` access off.
2. Create an API token scoped to that bucket with Object Read & Write. It supplies `R2_ACCOUNT_ID`,
   `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, and the bucket name is `R2_BUCKET`.
3. Add a **Cache Rule that bypasses the edge cache for `media.<domain>`**. Objects are stored `immutable` for a year
   and Cloudflare keeps serving a cached object after it is deleted from R2, while homie tells users deletion is
   immediate. Browsers still cache. If R2 reads grow later, use a 2-hour Edge TTL (the Free-plan minimum) and adjust
   the privacy wording.

## 5. Email

Email is **Resend Pro** ($20 a month: the free plan allows only 100 emails a day, and every login is one), sending from
the EU region, over SMTP.

1. In Resend, open **Domains**, choose **Add Domain**, enter `<domain>` and select **Ireland (`eu-west-1`)**. Choose the
   region now: changing it later means deleting the domain and adding it again with new DNS records.
2. Copy the records from its **Records** tab into Cloudflare DNS exactly as shown: the DKIM `TXT`, and the SPF `TXT` and
   `MX` of the Return-Path subdomain (`send.<domain>` by default). If a record is a `CNAME`, set it to **DNS only**.
   Wait until Resend shows the domain as verified, usually within minutes and up to 72 hours.
3. Add a `TXT` record named `_dmarc` with `v=DMARC1; p=none`. Tighten it to `p=quarantine` after a clean week.
4. Leave **click and open tracking off** (Resend's default): these are login and security emails. If click tracking is
   ever turned on, its tracking subdomain must serve https, because the web's HSTS header has `includeSubDomains`.
5. Create an API key that can only send, restricted to `<domain>`, and keep it in the password manager. Its value cannot
   be viewed again, and it is the SMTP password.

`SMTP_URL` and `EMAIL_FROM` go in through `fly secrets import` in section 6, so the key stays out of the shell history.
`smtps://` on port 465 is implicit TLS, which is what homie's mail sender uses for that scheme.

## 6. API

The API and worker are one Fly app and share these secrets. `EMAIL_BLOCK_KEY` is **never rotated** (it keys the
deleted-account email hashes), so generate it with `openssl rand -hex 32` and keep it in the password manager first.

```sh
fly secrets set SECRET_KEY=$(openssl rand -hex 32) --stage -a homie-api
fly secrets set NOMINATIM_USER_AGENT="homie/1.0 (+https://<domain>)" --stage -a homie-api
fly secrets import --stage -a homie-api   # paste these lines with real values, then Ctrl-D
```

`fly secrets import` reads the lines below from stdin, so the values stay out of the shell history. It keeps quotes
literally: do not quote anything.

```text
DATABASE_URL=<direct connection string from section 2, scheme postgresql+psycopg://>
REDIS_URL=redis://:<redis password>@homie-redis.internal:6379/0
EMAIL_BLOCK_KEY=<generated value>
SMTP_URL=smtps://resend:<resend-api-key>@smtp.resend.com:465
EMAIL_FROM=noreply@<domain>
WEB_ORIGIN=https://<domain>
PHOTO_PUBLIC_BASE_URL=https://media.<domain>
R2_ACCOUNT_ID=<account id>
R2_ACCESS_KEY_ID=<access key id>
R2_SECRET_ACCESS_KEY=<secret access key>
R2_BUCKET=<bucket name>
CONTACT_EMAIL=<contact address>
```

`CONTACT_EMAIL` is the same public address `make deploy-web` uses. The API and worker refuse to start without it.

Optional, each off without its values: Google sign-in and Sentry and PostHog, in section 8.

```sh
make deploy-api
fly certs add api.<domain> -a homie-api
```

Add a CNAME from `api` to `homie-api.fly.dev` at Cloudflare, **DNS-only (grey cloud)**: Fly issues the certificate
and `Fly-Client-IP` must stay the visitor's address.

```sh
curl https://api.<domain>/health        # must answer {"status":"ok",...}
fly scale count app=1 worker=1 -a homie-api   # exactly one worker: arq crons
```

**Areas, once, after the first deploy.** Until then the app runs on migration `0031`'s 19 settlements.

```sh
make import-areas-prod
```

It loads every settlement from the committed `api/data/settlements.csv` and makes no outside request. Read the counts
it prints: expect about 1,188 settlements, `neighbourhoods: 0` and `files_failed: 0`. It is safe to run again.

**Production never contacts nadlan.gov.il** (decided 2026-11-18): its terms forbid commercial use without written
approval and automated collection. `RENT_REFERENCE` and `CBS_RENT` stay `off`, so launch has no big-city neighbourhoods
and no official rent figures.

## 7. Admin

```sh
fly mpg users create <cluster id> -u homie_admin -r reader
fly mpg users rotate-password <cluster id> -u homie_admin   # prints the password; keep it for ADMIN_DATABASE_URL
```

**Probe first.** This is the first look at how a Reader really behaves:

```sh
fly mpg connect <cluster id> -u homie_admin -d <db> \
  -c "select current_user, session_user" \
  -c "set role none" \
  -c "select current_user, rolbypassrls from pg_roles where rolname = current_user" \
  -c "select rolname, rolsuper, rolbypassrls from pg_roles where pg_has_role(current_user, oid, 'MEMBER')" \
  -c "select has_table_privilege(current_user, 'users', 'UPDATE') as users_update, has_table_privilege(current_user, 'user_passwords', 'INSERT') as hash_insert, has_table_privilege(current_user, 'user_passwords', 'SELECT') as hash_select"
```

After `set role none`, `current_user` must be `homie_admin`, `rolbypassrls` false, and `users_update` and
`hash_insert` false. In the list of roles it belongs to, **stop if any row shows true**. `hash_select` may be true: the
next step hides those rows. **If anything else shows, stop and bring it to the orchestrator.**

**If Fly's Reader has `BYPASSRLS` or superuser, or can otherwise reach the hash tables, `make admin-role-prod` refuses.
Decided by Gilad on 2026-11-18: stop, leave the admin undeployed and ask Fly for a narrower role.** Do not work around
the refusal. Any other refused statement rolls back whole: stop and bring the error. A lock timeout only means a table
was busy: run it again.

```sh
make admin-role-prod   # grants, row-level security on the two hash tables, post-check
fly secrets set ADMIN_SECRET_KEY=$(openssl rand -hex 32) --stage -a homie-admin
fly secrets import --stage -a homie-admin   # paste, then Ctrl-D
```

```text
ADMIN_DATABASE_URL=postgresql+psycopg://homie_admin:<password>@<direct host>:5432/<db>
ADMIN_PASSWORD=<16 or more characters, kept in the password manager>
```

`<password>` is the one `rotate-password` printed, `<direct host>` the host of section 2's direct connection string.

```sh
make deploy-admin
make admin-role-verify-prod   # must pass
fly ips list -a homie-admin   # must be empty
fly proxy 8001:8001 -a homie-admin
```

If `make admin-role-verify-prod` fails, stop the admin: `fly machine list -a homie-admin`, then
`fly machine stop <machine id> -a homie-admin`.

Open <http://localhost:8001/admin> in Chrome, which keeps the `Secure` cookie on `localhost`. If a browser drops it,
set `ADMIN_HTTPS_ONLY=false` in `infra/fly/admin.toml` through a PR: the path is loopback plus Fly's WireGuard, already
encrypted.

Re-run `make admin-role-prod` and `make admin-role-verify-prod` after any migration that adds a table or changes the
admin's columns.

## 8. Web

```sh
cd web && pnpm dlx wrangler@4.156.1 pages project create homie --production-branch main; cd ..
make deploy-web DOMAIN=<domain> CONTACT_EMAIL=<contact address>
```

Attach `<domain>` as the Pages project's custom domain. Optionally add a `www` to apex redirect rule: CORS allows only
the apex.

**Google sign-in (optional).** In the Google OAuth client add `https://<domain>` as an authorised JavaScript origin and
publish the consent screen. Then:

```sh
fly secrets set GOOGLE_VERIFIER=google GOOGLE_CLIENT_ID=<client id> --stage -a homie-api
```

Put `VITE_GOOGLE_CLIENT_ID=<client id>` in the deploy checkout's git-ignored `.env`, and run `make deploy-api` and
`make deploy-web`.

**Sentry and PostHog (optional).** Set these with `fly secrets import --stage -a homie-api`, then run the same two
deploys:

```text
SENTRY_DSN=<DSN of an EU-region (de.sentry.io) project>
POSTHOG_KEY=<project key>
POSTHOG_PERSONAL_API_KEY=<personal key with scope person:write only>
POSTHOG_PROJECT_ID=<numeric project id>
```

`make deploy-api` passes the git sha as `SENTRY_RELEASE` on every deploy. The web build's `VITE_SENTRY_DSN`,
`VITE_POSTHOG_KEY` and the build-only `SENTRY_AUTH_TOKEN`, `SENTRY_ORG` and `SENTRY_PROJECT` go in the same `.env`.

In the EU PostHog project turn on **Cookieless server hash mode** (without it cookieless events are dropped) and
**Discard client IP data**. After the first account deletion check that `posthog_forget_job` got a 202 and that
`persons_queued_for_deletion` shows it in PostHog: that request body was never tried against a real project.

## 9. Smoke test (before telling anyone)

**Fly-Client-IP check.** Send 4 OTP requests for an address you own, each with a different forged header:

```sh
for n in 1 2 3 4; do
  curl -s -o /dev/null -w '%{http_code}\n' -X POST https://api.<domain>/auth/otp/request \
    -H 'Content-Type: application/json' -H "Fly-Client-IP: 203.0.113.$n" -d '{"email":"<your address>"}'
done
```

The 4th must answer **429**: the per-(email, network) limit is 3 per 15 minutes and counts the real address only if
Fly overwrites the client's header. If the 4th answers 204, **stop and keep homie private**, and bring it to the
orchestrator. Wait 15 minutes before the sign-up step, or use another address.

Then check each of these:

- [ ] The landing page loads.
- [ ] Sign up with a real address: the code arrives, not in spam.
- [ ] Post a listing with a photo: it shows from `media.<domain>`, and its map pin appears after the worker's geocode
      sweep.
- [ ] Open a chat in a second browser: a message arrives live over SSE. In DevTools `/me/events` shows protocol `h2`,
      `text/event-stream`, **no** `content-encoding`, and stays open past 2 minutes.
- [ ] `curl --http2 -s -D- -o /dev/null -H 'Accept-Encoding: gzip' https://api.<domain>/areas` shows `HTTP/2 200` and
      `content-encoding: gzip`.
- [ ] The city picker offers settlements across Israel.
- [ ] Log in with a password, and with Google if it is on.
- [ ] Book a tour between the two accounts: the email with its `.ics` arrives. Press "הוספה ליומן Google" and check the
      tour appears in Google Calendar (Google may take hours to fetch a new feed). `fly logs -a homie-api` must show
      `/tour-feed/[redacted]`, never the token.
- [ ] Delete a listing photo: its `media.<domain>` URL answers 404 from a fresh client (no browser cache).
- [ ] Delete a test account: it can no longer log in.
- [ ] The map draws its tiles.
- [ ] The PWA installs.
- [ ] DevTools shows no `Refused to …` CSP line on the landing, search, map, listing, chat and profile pages. To roll
      back a violation, edit `web/public/_headers` and `web/scripts/build-check.mjs` through a PR and run
      `make deploy-web`.

## 10. Restore drill (before launch, then quarterly)

```sh
fly mpg backup list <cluster id> --all
fly mpg restore <cluster id> --backup-id <backup id> --name homie-restore-drill
```

The restore creates a **new cluster, billed until destroyed**. Connect to it and compare the row counts of `users`,
`listings` and `messages` with production (the restored counts may be lower: the backup is older). Check
`alembic_version` and `postgis_version()`. Write down how `DATABASE_URL` and `ADMIN_DATABASE_URL` would be switched to
it. Then destroy it with `fly mpg destroy <restored cluster id>`, and record the date and the time it took at the
bottom of this file.

## 11. Day-2

- **Deploy** = `make deploy-redis`, `make deploy-api`, `make deploy-admin` and `make deploy-web` from a clean `main`
  (`make deploy-web` needs `DOMAIN` and `CONTACT_EMAIL`). Deploy only what changed; Redis at a quiet hour.
- **Roll back:** `fly releases --image -a <app>` lists the images; `fly deploy --image <image> --config
  infra/fly/<name>.toml --skip-release-command` redeploys one. Without that flag the release step runs the old image's
  `alembic upgrade head`, which fails on a newer revision it does not know and aborts the rollback. A rollback undoes no
  migration, so the old code must work with the newer schema; if it cannot, fix forward instead.
- **A release that changes the admin's grants** (a new table, or changed admin columns) deploys in this order:
  `make deploy-api` (migrates), `make admin-role-prod`, `make deploy-admin`, then `make admin-role-verify-prod`.
- **Logs:** `fly logs -a homie-api`. Fly's docs say logs are kept 7 days (checked 2026-11-18), inside the 30 days the
  privacy policy promises. A log shipper, if one is added, is set to 30 days.
- **Each deploy** drops SSE streams and requests for about 10 to 30 seconds (one API machine); the web reconnects.
- **`/health` answers 503 while Redis is down**, and a failing check stops Fly routing to the machine. So
  `make deploy-redis` or a Redis blip takes the **whole API** offline, browsing included, until Redis is back.
- **Redis memory alert.** Redis refuses writes at 200 MB (`noeviction`), which would stop logins. In Fly's managed
  Grafana (fly-metrics.net, free) add an alert that emails Gilad when this query passes 0.7 (70% of the 256 MB VM):

  ```text
  1 - fly_instance_memory_mem_available{app="homie-redis"} / fly_instance_memory_mem_total{app="homie-redis"}
  ```

  The metric names are from Fly's metrics docs; confirm them in Grafana when creating the alert. Once, read the idle
  baseline and write it here: run `fly ssh console -a homie-redis`, then `REDISCLI_AUTH="$REDIS_PASSWORD" redis-cli INFO
  memory`. Idle baseline: _not measured yet_. If the alert fires, look at `INFO memory`, then raise the VM and
  `--maxmemory` (`infra/Dockerfile.redis`) together.
- **If Redis's volume is lost:** create a new one (section 3) and `make deploy-redis`. It costs live OTP codes,
  rate-limit counters, one minute of views, the arq queue and any **tour emails still queued** (`tour_mail`). Those
  emails are not re-sent; the tours themselves are in Postgres and the geocode sweep re-finds its work.

## 12. Waitlist on `join.<domain>`

The waitlist is live on `homie-waitlist.pages.dev`; the steps are in `waitlist/README.md`. In this order:

1. Add `join.<domain>` to the Turnstile widget's hostnames.
2. Commit `ALLOWED_ORIGIN = "https://join.<domain>"` in `waitlist/wrangler.toml` through a PR.
3. Run `make deploy-waitlist`.
4. Add the custom domain on the Pages project.
5. Add the zone's one free rate-limit rule for `/api/signup`.
6. Send one test signup and remove it with `make waitlist-delete`.

After this `homie-waitlist.pages.dev` refuses signups, so update any link that points there first.
