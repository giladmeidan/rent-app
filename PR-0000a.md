## What was built

- `infra/docker-compose.yml`: `db` (postgis/postgis:16-3.4, healthcheck `pg_isready`), `redis` (redis:7-alpine, healthcheck), `api` (uvicorn `--reload`, :8000, source bind-mounted), `worker` (arq). Host ports are overridable via `DB_PORT` / `REDIS_PORT` (default 5432 / 6379) because the compose defaults collided with services already running on this machine. `infra/Dockerfile.api` builds on `ghcr.io/astral-sh/uv:0.12.16-python3.12-trixie-slim` with the venv at `/opt/venv` so the bind mount does not hide it.
- `Makefile`: `dev`, `down`, `migrate`, `seed`, `test`, `lint`. `dev` = compose `up -d --wait db redis` → `migrate` → `seed` → `up -d --build api worker`. Local defaults for `DATABASE_URL`/`TEST_DATABASE_URL`/`REDIS_URL`/`WEB_ORIGIN` are exported from the Makefile and match `.env.example`.
- `api/`: uv project (`pyproject.toml` + `uv.lock`, every dependency pinned `==`), `app/main.py` (factory, CORS for `WEB_ORIGIN`), `config.py` (pydantic-settings, env only), `db.py` (sync SQLAlchemy 2.0, `postgresql+psycopg`, session dependency), `models/area.py`, `schemas/area.py` (`AreaOut`, no geometry), `schemas/health.py` (`HealthOut`, so the 503 shape is in OpenAPI), `services/areas.py::list_active_areas`, `services/health.py` (`ping_db`, `ping_redis`), `routers/health.py`, `routers/areas.py`, `worker.py` (arq `WorkerSettings` with `ping`), empty `matching/`, `i18n/`.
- Alembic: `alembic.ini` (`script_location = %(here)s/alembic`, works from any cwd), `env.py` using `Base.metadata` and `DATABASE_URL` (a programmatic `sqlalchemy.url` wins, which is how tests target other databases), migration `0001_areas` (postgis extension `IF NOT EXISTS`, `areas` table, GiST `ix_areas_geom`; downgrade drops index + table, keeps the extension).
- `api/scripts/seed.py` (`ON CONFLICT (slug) DO NOTHING`, WKT via `ST_GeomFromText`, no shapely), `api/scripts/export_openapi.py`.
- `.github/workflows/ci.yml`: job `api` with postgis + redis service containers; `astral-sh/setup-uv@v6` pinned to 0.12.16, `uv sync --frozen`, then `make lint` and `make test`.
- `README.md`, `.env.example` (`DATABASE_URL`, `TEST_DATABASE_URL`, `REDIS_URL`, `WEB_ORIGIN`).

Dependency notes: `redis` is pinned to 5.3.1 (not 8.x) because `arq==0.28.0` requires `redis<6`. SQLAlchemy pinned to 2.0.57 (latest 2.0.x; 2.1 exists but the spec says SQLAlchemy 2.0 style). No `ignore_missing_imports` override was needed: geoalchemy2 0.21 and arq 0.28 both ship `py.typed`, so `mypy --strict` passes on `app/`, `scripts/`, `tests/` and `alembic/` without any override.

## Out of scope, noticed (not fixed)

- Starlette 1.10 emits `StarletteDeprecationWarning: Using httpx with starlette.testclient is deprecated; install httpx2 instead` once per test session. The spec names `httpx`, so it stays; a later spec may swap to `httpx2`.
- On this machine ports 5432, 5433 and 6379 are already taken by non-Docker services, so `make dev` needs `DB_PORT=5434 REDIS_PORT=6380` here. Documented in README → Configuration; a committed `.env` convention for compose overrides could follow if it keeps biting.
- Branch protection making the `api` job required is a GitHub setting Gilad flips after merge (and after the remote exists).
- `types-redis` (4.6 stubs) shadows redis-py 5's own inline types; harmless today (`from_url`, `ping`, `close`), worth dropping when a later spec touches redis more.
