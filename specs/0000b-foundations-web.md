## Goal
After this ships, `make dev` also brings up the Vite dev server; opening http://localhost:5173 shows a Hebrew,
right-to-left app shell that fetches the active launch areas (Gush Dan) from `GET /areas` (built in `0000a`);
`make client`, `make e2e`, `make i18n-check` exist and `make test` / `make lint` cover the web; CI runs the `web`
and `e2e` jobs on every PR. Serves Dev Plan slice 0 (Foundations), part b of two. No product behaviour.

## Build notes (orchestrator, 2026-11-10)
Facts about the repo as merged in `0000a` that the Scope lines above must respect:
- Ports are env-driven and bound to loopback. The `web` service publishes `127.0.0.1:5173:5173` (Vite listens on
  `0.0.0.0` inside the container) and gets `VITE_API_URL=http://localhost:${API_PORT:-8000}`, not a fixed 8000.
- CORS allows exactly `WEB_ORIGIN` = `http://localhost:5173`. The browser, Playwright `baseURL` and the e2e readiness
  wait all use `http://localhost:5173`; `http://127.0.0.1:5173` is refused by the API. The API readiness wait uses
  `http://127.0.0.1:$(API_PORT)/health`, as `make dev` already does.
- The api publishes on IPv4 loopback only. The browser calls the API directly (no Vite proxy in this slice); if a
  proxy is ever added it must target `127.0.0.1`, because Node resolves `localhost` to `::1` first.
- `make client` runs `export_openapi.py` through `$(UV)` inside make, so the Makefile's exported defaults
  (`DATABASE_URL`, `REDIS_URL`, `WEB_ORIGIN`, and `SECRET_KEY` once `0001a` merges) reach it; the CI `web` job calls
  `make client`, never the script directly.
- `.gitignore` currently ignores `web/src/api/*.gen.ts`; change it to the generated `web/src/api/schema.d.ts`.
- Node 22 via `web/.nvmrc` and `engines`; pnpm version pinned in `packageManager`.

## Risks / open questions
- `i18n-check` heuristics ("≥2 consecutive Latin words") will have false positives; the exclusions above (attributes, tests, locales, manifest, vite config) are the full allowed list. If the coder hits another false positive, add a `// i18n-ignore-next-line` comment convention and test it, rather than widening the heuristic.
- Hebrew copy in `he.json` and the manifest name "דירה" are placeholders; Slice 9 owns final branding. Not a blocker — the strings are specified, nothing to guess.
- e2e in CI builds the compose images cold; if NF1 is at risk, cache docker layers (`docker/build-push-action` cache) before relaxing the budget.
- No open product questions.
