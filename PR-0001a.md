## What was built

- Migration `0002_users_sessions` (`revision="0002"`, `down_revision="0001"`); models `User`, `Session` in `api/app/models/`, mirroring it (named CHECKs, `Index("ix_sessions_user_id")`), exported from `models/__init__.py`.
- `api/app/schemas/auth.py`: `OtpRequestIn`, `ProfileIn` (`str_strip_whitespace`, 2–40), `OtpVerifyIn` (`^[0-9]{6}$`), `UserOut`.
- `api/app/services/auth.py`: `request_otp`, `verify_otp`, `create_session`, `revoke_session`, `resolve_session` and the spec's constants. Details worth a reviewer's eye:
  - Rate limits: the three counters are created and incremented in one `MULTI` (`SET k 0 EX w NX`, `INCR`, `TTL` each); `Retry-After` is the largest remaining TTL among the counters that tripped. A limited request still counts (the counters are incremented before the check).
  - Attempts: a small Lua script reserves an attempt atomically (`EXISTS` → `HINCRBY` → return `code_hmac`) **before** the `hmac.compare_digest`, so concurrent guesses cannot exceed 5 per code, and a verify for a missing key never creates a key without TTL. A right code with no account and no profile refunds the attempt (second script), so `attempts` stays 0 (AC2).
  - Concurrent first verify: implemented with `INSERT … ON CONFLICT (email) DO NOTHING RETURNING` followed by a lookup of the winning row, rather than catching `IntegrityError`. Same contract (200 login of the winner, never a 500) without rolling back the transaction.
  - The OTP key is deleted after the user commit, so a DB failure leaves the code usable.
- `api/app/services/email.py` (`EmailSender`, `FileEmailSender`, `SmtpEmailSender`, `EmailUnavailable`, `get_email_sender`); `SmtpEmailSender` passes `ssl.create_default_context()` to both `SMTP_SSL` and `starttls` (certificate verification on). `api/app/services/sms.py` (`SmsSender`, `NoopSmsSender`, no caller). `api/app/i18n/he.py` (subject and three-line body, code alone on line 2).
- `api/app/redis_client.py` (`get_redis`, cached, 1 s timeouts), `api/app/auth.py` (`current_user`, `optional_user`, `COOKIE_NAME`), `api/app/routers/auth.py` (four endpoints; errors documented in OpenAPI).
- Config: `Settings` (only) gains `secret_key`, `email_backend`, `email_outbox_dir`, `smtp_url`, `email_from`, `cookie_secure`. `SECRET_KEY` default in the Makefile, both compose services, CI `env:`, `.env.example` (plus the email/cookie variables and a commented `SMTP_URL`). Compose `api`: `EMAIL_BACKEND=file`, `EMAIL_OUTBOX_DIR=/outbox`, volume `../.outbox:/outbox`. `make dev` runs `mkdir -p .outbox && chmod 0777 .outbox` before compose; `make down` runs `rm -f .outbox/*.json`. `.outbox/` in `.gitignore`, `**/.outbox` in `.dockerignore`.
- `conftest.py`: `db_engine` truncates `sessions, users, areas`; fixtures `redis_clean` (SCAN + delete `otp:*`, `rl:*`) and `outbox` (in-memory sender via `app.dependency_overrides[get_email_sender]`).
- README: "Logging in locally".
- Dependency: `pydantic[email]==2.14.3` with `email-validator==2.3.0` pinned (pulls `dnspython==2.9.2`).

The 35 tests from 0000a pass unchanged. `test_config.py` and `test_migrations.py` were only appended to; `conftest.py` changed as the spec says.
